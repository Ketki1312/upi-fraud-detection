   306→-   Audit transaction and message datasets.
   307→
   308→-   Calculate row counts, columns, types, missing values, duplicates,
   309→    label distributions, category/language distributions, amount
   310→    statistics and temporal patterns.
   311→
   312→-   Generate data_audit_report.json and Markdown documentation.
   313→
   314→-   Never alter raw files.

   316→PHASE 2 — TRANSACTION PREPROCESSING
   317→
   318→-   Target: isFraud.
   319→
   320→-   Initial features: step, type, amount, oldbalanceOrg, newbalanceOrig,
   321→    oldbalanceDest, newbalanceDest.
   322→
   323→-   Do not directly use nameOrig/nameDest unless a clearly justified
   324→    non-leaky derived behavioural feature is created.
   325→
   326→-   Investigate balance-change, amount/balance ratio, transaction-type

   329→-   Use chronological/temporal evaluation where appropriate because
   330→    concept drift is a core requirement.
   331→
   332→-   Document the exact split strategy.
   333→
   334→PHASE 3 — TRANSACTION MODELS
   335→
   336→-   Train Logistic Regression, Random Forest and XGBoost.
   337→
   338→-   Handle extreme class imbalance appropriately.
   339→
   340→-   Evaluate Precision, Recall, F1, ROC-AUC, confusion matrix and PR-AUC
   341→    where appropriate.
   342→
   343→-   Save trained model, preprocessing pipeline, feature metadata,
   344→    metrics and model version.
   345→
   346→-   Do not select a model by hardcoded preference.
   347→
   348→PHASE 4 — MULTILINGUAL MESSAGE PIPELINE
   349→
   350→-   Unify English, Hindi and Hinglish into text, language, category,
   351→    label, source.
   352→
   353→-   Perform Unicode normalization, whitespace normalization, safe
   354→    cleaning, duplicate detection and label validation.
   355→
   356→-   Do not destroy meaningful Hindi/Hinglish signals such as URLs,
   357→    numbers, currency symbols, OTP-like patterns or emojis without
   358→    justification.
   359→
   360→PHASE 5 — NLP BASELINE
   361→
   362→-   Build TF-IDF + Scikit-learn classifier.
   363→
   364→-   Evaluate English, Hindi, Hinglish and combined multilingual data.
   365→
   366→-   Report Precision, Recall, F1 and ROC-AUC where meaningful.
   367→
   368→-   Prevent duplicate/template leakage.
   369→
   370→PHASE 6 — MULTILINGUAL TRANSFORMER
   371→
   372→-   Use PyTorch + Hugging Face Transformers.
   373→
   374→-   Select a multilingual model supporting English/Hindi and reasonably
   375→    handling Hinglish.
   376→
   377→-   Document model choice and computational requirements.
   378→
   379→-   Fine-tune/evaluate and save tokenizer, model, configuration, metrics
   380→    and version.
   381→
   382→-   Provide CPU fallback if GPU is unavailable.
   383→
   384→PHASE 7 — UNIFIED RISK ENGINE
   385→
   386→-   Convert transaction and message probabilities into a standardized
   387→    0–100 risk score.
   388→
   389→-   Risk levels: LOW, MEDIUM, HIGH, CRITICAL.

   393→-   Do not imply that public datasets contain direct transaction-message
